# Morning import runbook: v4 glassies (and the other waiting meshes)

One safe flow from "the Open Cloud key works" to "the new art is live in Studio". Every step can be re-run: uploads skip files whose hash is unchanged, and the installer skips models already at v4 from the same asset. Nothing replaces live art without a backup.

What gets installed:
- the **24 revamped glassies** (v4 art over the current release models)
- the **12 Roster V2 launch glassies** (new models)
- the waiting meshes from other workstreams: flyers v3 (H), finishers v3 (G) and the Hollowlight v5 carriage (I)

## 0. Fix the key (creator, about 2 minutes)

Open Cloud asset uploads return **403** until the key has asset permission.

1. Creator Hub > Open Cloud > API Keys > the Glass Clash key > Access Permissions > add **Assets** with **Read** and **Write**.
2. Make sure the key is allowed to create for **group 11116787**.
3. Save. The key value doesn't change, so `ROBLOX_ASSETS_KEY` keeps working.

## 1. Check (Terminal, repo root)

```bash
zsh -i -c 'python3 tools/opencloud/upload_assets.py --check'
```

- Expected: `assets: OK`.
- Still `assets: HTTP 403 ...`: step 0 isn't saved yet, or the key isn't allowed for the group.

## 3. Install the glassies in Studio (Edit mode, Studio MCP)

```bash
tools/studio_lock.sh acquire glassy-install
```

Studio must be in **Edit** (not Play), with Rojo connected. Then:

1. **Register the installer** (once per Studio session):

   ```bash
   python3 tools/studio/glassy_install_chunk.py --installer-only --out /tmp/gc_installer.luau
   ```

   Run the file's contents with the Studio MCP `execute_luau` (Edit). Expected: `installer registered as _G.GlassyInstallV4`.

2. **Dry run**, in batches of about 6 (a chunk carries about 11 KB per glassy):

   ```bash
   python3 tools/studio/glassy_install_chunk.py --split --mode dry pop jam prism milk_bottle pickle_jar ketchup_bottle --out /tmp/gc_1.luau
   ```

   Run it. Every glassy should report:
   - `Status = "would replace ReplicatedStorage.Assets.Glassies.<id>"` (revamp) or `"would add ..."` (launch)
   - `Scale` around `0.01`, because Open Cloud FBX models arrive 100× like the manual imports
   - `FitError` and `MaxBoundsError` below `0.003`
   - `Parts` with Body 1, Shard 16–20
   - `Warnings` empty

   A `FAILED` entry carries its reason, such as a missing mesh name or no rotation fitting, and nothing has changed.

   Batches:
   - `pop jam prism milk_bottle pickle_jar ketchup_bottle`
   - `glass_cup water_jug lemonade_bottle mason_jar hot_sauce crystal_tumbler`
   - `chime crescent_axe briar_flask arc_coil hourglass frostglobe`
   - `rocket_pop prism_blade glass_duck comet glass_dragon galaxy_orb`
   - `fishbowl cookie_jar glass_top bubble_wand piggy_bank light_bulb`
   - `potion_flask honey_bear crystal_ball grizzly_guardian glass_unicorn glass_phoenix`

3. **Install**: same batches, `--mode install`. Expected: `Status = "installed"`.
   - Each replaced model is first copied to `ServerStorage.GlassiesBeforeV4.<id>` (only the first time; never overwritten).
   - The raw insert is kept in `ServerStorage.GlassyV4Import.<id>`.
   - Running a batch again prints `unchanged (already v4 from asset ...)`.
4. **Verify everything**:

   ```bash
   python3 tools/studio/glassy_install_chunk.py --split --mode verify --set revamp --out /tmp/gc_vr.luau
   ```

   Then the same with `--set launch`. Expected: every glassy has `Ok = true` and `Problems = {}`. The check covers `MotionVersion` and every `Pivot_<Detail>` attachment.
5. Release the lock:

   ```bash
   tools/studio_lock.sh release glassy-install
   ```

   Then the creator **saves or publishes the place**.

What the installer builds, at the same path the game already reads (`ReplicatedStorage.Assets.Glassies.<id>`):
- **Layout:** a Model with pivot at the hang point, holding the `Body` MeshPart (PrimaryPart), a `Details` folder and a `Shards` folder.
- **Per part:** the manifest colour, material, transparency (two-layer glass), reflectance and centre. Collisions and shadows are off.
- **Part attributes:** `SourceName`, `AssetRole`, `EffectOnly`, `AnimationPivot` and `MotionJson` (idle and hit motion for the presentation code).
- **Model attributes:**
  - `ReleaseVersion = 2` (kept on purpose: it switches FightScene to the release crack paths)
  - `ArtVersion = "v4"`, `SourceAsset`, `IconAsset`
  - `MeasuredRadius` and `MeasuredCenter`
  - **`MotionVersion = 4`** (3 for a v3 install). GlassyMotion (workstream E) only animates models that carry it, so old v2 models that share detail names (`Wing`, `Cap`) are never driven with the new pivots.
- **Explicit pivots:** every animated part gets an Attachment **`Pivot_<Detail>`**.
  - It sits at the manifest's `pivot_roblox`, and its primary `Axis` is the manifest's `axis_roblox`; the `MotionAxis` attribute holds the same vector.
  - It's created by the installer because the FBX files carry meshes only: the Blender `Pivot_` empties never come through the import.
  - Verify mode checks that each one exists and sits within 0.002 studs of its manifest position.

Checked on Oct 19, through the same installer in Studio:
- Pop's raw release_v2 FBX import (ServerStorage.CombatReleaseBackups) fitted at scale 0.01 with the 180° yaw, bounds error 5e-7, Radius/Center 0.65/1.375 (equal to ReleaseGeometry).
- Install, verify and a second install ran into a sandbox library: the backup was kept, then the sandbox was removed and the live models were untouched.
- An existing Open Cloud FBX model (asset 115123551485957) loads at 100× with identity rotations and FBX node names, the case the fit handles.

## Rollback

For any glassy, in Edit:

```lua
local RS, SS = game:GetService("ReplicatedStorage"), game:GetService("ServerStorage")
local id = "pop"
local backup = SS.GlassiesBeforeV4:FindFirstChild(id)
if backup then
	if RS.Assets.Glassies:FindFirstChild(id) then
		RS.Assets.Glassies[id]:Destroy()
	end
	backup:Clone().Parent = RS.Assets.Glassies
end
```

Launch glassies have no backup, because they are new; remove the model to roll back. Place version history in Creator Hub covers everything else.
